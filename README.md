
# STBD —— Terminal TUI 编辑器

> 名字取自网名 summerTBD。之前叫 CCE（Command Code Editor），因为 `cce` 在 crates.io
> 上已被占用（commandline compiler explorer），改成了 STBD。

## 项目概述
构建一个基于 Ratatui 的终端用户界面（TUI）编辑器，支持三种模式：
- 只读模式（ReadOnly）：浏览内容，不可修改
- 编辑模式（Edit）：自由编辑文本内容
- 命令模式（Command）：在底部命令行输入命令执行操作

## 核心功能需求

### 1. 编辑器模式
- **只读模式**：用户可以浏览文本，光标可移动，但无法修改内容
- **编辑模式**：用户可以插入和删除字符，光标自由移动
- **行选择模式**（只读模式下按 `V`）：圈住**整行**（`j`/`k` 拉大拉小），
  `y` 复制 / `d` 剪切 / `Delete` 只删。除了后两个（那是你明确要求改文档），
  这个模式里一个键都不会碰你的文件 —— 「调选区」和「改文件」分开，才不会手一抖就改了代码
- **命令模式**：键盘输入聚焦到底部命令行，支持命令输入和执行（提示符 `:`）
- **外部命令模式**：键盘输入聚焦到底部命令行，回车后**把终端整个让给 shell**（提示符 `!`）

### 2. 界面布局
- **左上角**：显示标题 "STBD"
- **主体区域**：显示文本内容（可滚动）
- **最底部一行**：命令行输入栏
  - 命令模式下显示光标和输入内容
  - 其他模式下显示当前模式状态（如 `-- 只读模式 --`）

### 3. 交互操作
- **模式切换**：
  - `Esc`：切换到只读模式
  - `:`：从只读模式切换到命令模式
  - `!`：从只读模式切换到外部命令模式
  - `insert/i`：从命令模式切换到编辑模式
  - `v`：从只读模式进入**行选择模式**（再按一次 `v` 或 `Esc` 退出）
- **只读/编辑模式操作**：
  - `h/j/k/l` 或方向键：移动光标
  - `q`：**回到上一个打开的文档**（像 ranger 那样）；已经是最早那个才退出程序
  - `Enter`：当前若在目录列表里，打开光标所在行的那个条目
  - `y`：复制当前行到系统剪贴板（仅只读模式；圈了选区那就是复制选区）
- **行选择模式操作**（先按 `v`）：
  - `j`/`k` 或 `↑`/`↓`：拉大 / 拉小选区（**只动选区，不动文档**）
  - `h`/`l`：把这一段**整体下移 / 上移一行**（`h` 下、`l` 上）
    - 连按就是一行一行地挪；**选区跟着块走**，不会按两下就换了那一段
    - 挪到文件头 / 尾就说一句，不会绕到另一头去
    - ⚠️ 这和只读模式的 `h`/`l`（左右）**不同义**：行选区没有左右可言，它们就空出来了
  - `y`：复制选区　`d`：剪切（进剪贴板 + 删掉）　`Delete`：只删（不碰剪贴板）
  - `d` 和 `Delete` 都改文档、都**可撤销**（各算一步）；区别只有碰不碰剪贴板
  - `Esc` / `v`：取消选区
  - 圈住的都是**整行**：不做字符选择（那要引入「列」，而复制/剪切/删除这三件事全是按行干的）
  - 选区只是「**坐标已知的一对行号**」：`y` / `Delete` 走的**就是**
    `:copy <起> <终>` / `:delete <起> <终>` 那两条实现；移行也不是新机制 ——
    一段 N 行挪一格 = **N 次相邻交换**，用的就是 `:swap` 那个原语

> **只读 / 行选择模式里的字母键不挑大小写** —— `Y` 和 `y`、`V` 和 `v` 是同一件事，
> 少按一次 Shift 不该变成「这个键没反应」（`Ctrl+Shift+R` 也等于 `Ctrl+R`）。
> 编辑模式里不折（那里 `A` 和 `a` 是两个字符）；`:命令` 和 `!shell` 那两行也不折
> （`:open README.MD` 的路径得原样进去 —— 命令名不挑大小写是**命令层**的事）。

- **粘贴**：编辑模式下 `Ctrl+V` 粘贴（基于终端 bracketed paste，整段一次性插入；只读模式会提示先按 `i`）
- **编辑模式额外操作**：
  - 字母/数字/符号：插入字符
  - `Backspace`：删除前一个字符
  - `Delete`：删除当前字符
  - `Enter`：换行
- **命令模式操作**：
  - 输入命令字符
  - `Enter`：执行命令
  - `Esc`：取消命令，返回只读模式
- **外部命令模式操作**：
  - 输入任意 shell 命令行（内容**不会被我们解析**）
  - `Enter`：先退出界面，把刚才那一行以 `!命令` 写回终端（免得突兀），再把它交给 shell
  - 跑完（或 Ctrl+C 中断）后会看到 `press ENTER to return`，敲一下回车回到编辑器
  - `Esc`：取消，返回只读模式

### 4. 命令系统

> 词汇表与语法总则见 [`COMMANDS.md`](COMMANDS.md)。

**五条规矩**

- **不挑大小写** —— `:DELETE 1 2` 和 `:delete 1 2` 是同一件事，别名同样（`:D` / `:d`）；
  选项名和关键字参数同理（`--FORCE`、`:set NUMBER`）。
  ⚠️ 但**参数里的路径是你写的字**，一个字节都不动：`:open README.MD` 打开的就是
  那个大写名字的文件。
- **位置参数**保持书写顺序 —— 顺序就是含义（`delete 1 3` 的 1 是起点、3 是终点）。
- **选项**用 `-x` / `--xxx`，**命令名之后**放哪都一样（`:open a.rs --force` = `:open --force a.rs`）。
  ⚠️ 不能写到命令名**前面**：第一个词永远是命令名，所以 `-f back` 是「一条叫 `-f` 的命令」
  （跟 shell 一样 —— `-la ls` 里 `-la` 就是命令名）。要写 `back -f`。
  末尾的 `!` **不再认**：以前能写 `:q!` / `:stbd!`，现在统一成 `--force`
  （随手敲了旧写法，会得到一句怎么改的提示）。
- **`&&`** 把多条命令串起来，**前一条成功才做后一条**：
  `:copy 1 3 && delete 1 3`（复制完再删 = **移动**）。
  前面失败时链会**停在那里**，并在提示后面加一句 `(stopped; nothing after && ran)`。
- **引号**（`"..."` 或 `'...'`）把一串字符收成**一个**词：`:open "my file.rs"`。
  引号里空格和 `&&` 都不再是分隔符 —— 文件名里带这俩字符就得靠它。
  引号只改「边界」不改「身份」：`open "-x"` 里那个词仍然算选项（跟 shell 一样），
  要传以 `-` 开头的路径请用 `:` `--`（`:open -- -weird.rs`）。
  **不支持转义**（不认 `\"`）：要引号本身，换一种包（`':open "it's.txt"'`）；
  **引号必须包住整个词**（`"my dir"/x.rs` 会报错，写 `"my dir/x.rs"`）。

**外部命令是另一套语言**

`!` 不是命令前缀，是**按键** —— 按下去的那一刻就决定了这一行归谁：

- `:` 后面是**编辑器的**命令语言：我们自己分词、认 `&&`、认引号、查命令表。
- `!` 后面是 **shell 的**语言：一个词都不分，整行原样交给 `cmd /C` / `sh -c`。

好处是**没有「这行归谁」的判断**：`git commit -m "a b" && echo done` 里的 `&&`
是 shell 的 `&&`，`:copy && delete` 里的 `&&` 是我们的 —— 两者永远不会撞车。

回车之后会做什么：离开备用屏、关掉 raw 模式 / 鼠标捕获，让命令在**真终端**上跑，
等你敲回车再回来重画。所以编码（GBK）、颜色、交互式程序、超大输出**都不用我们管** ——
终端真的交给它了，我们一个字节都不碰。

> ⚠️ **代价：输出留不住**（跟随终端滚动，回去就看不见了），而且
> **所有后果由命令自己承担** —— 我们不做捕获、不做回显、不解析输出。
> 想把输出抓进一个只读视图是另一条路（Vim 的 `:r !` 那一半），还没做。

**退出与导航**

- `:q` / `:quit`（别名 `:exit` `:qa` `:quitall`）- **退出整个程序**
- `:back`（别名 `:prev` `:bprev`）- 回到上一个打开的文档
- `:next`（别名 `:bnext` `:n`）- 去下一个打开的文档
- `:ls`（别名 `:files`）- 列出打开过的文档（`*` 标当前）
- `:forget <n>` - 把第 n 个文档从列表里去掉（序号来自 `:ls`，不动磁盘上的文件）

> ⚠️ **`:q` 与 `q` 键不是一回事**：`q` **按键**有上一级就返回、没有才退出
> （ranger 手感）；`:q` **命令**永远退出（写进脚本 / `&&` 里不会有歧义）。

**文档与配置**

- `:open <path>`（别名 `:e` `:edit` `:stbd`）- 打开文件或目录（目录列出直接子项，子目录带 `/`）
- `:write`（别名 `:w`）- 保存；`:w <路径>` - **另存为**（写出去，并且缓冲区从此叫这个名字）；`:wq` - 保存并退出
- `:settings`（= `:config edit`）- 打开配置文件来编辑（还没有就照模板生成一份）
- `:reload`（= `:config reload`）- 重读配置文件，不用重启
- `:config` - 查看当前生效的设置；`:config path` - 看配置文件在哪

**编辑**

- `:delete <行>` / `:delete <起> <止>` / `:delete all`（别名 `:d` `:del`）- 删行（1 基，含两端）
- `:copy <位置> [<位置>]` / `:copy all`（别名 `:y` `:yank`）- 复制到系统剪贴板。
  位置写作 `行` 或 `行:列`（鄇 1 基）：`:copy 3`、`:copy 1 3`、`:copy 2:3 5:7`
- `:swap <行> <行>`（别名 `:sw`）- 交换两行
- `:insert`（别名 `:i`）- 进编辑模式；`:undo`（别名 `:u`）/ `:redo` - 撤销 / 重做

**设置**

- `:set number` / `:set nonumber` - 显示 / 隐藏行号
- `:set tabwidth <n>` / `:set scrolloff <n>` / `:set sidescrolloff <n>` - 改运行时的设置
- `:set lspmaxservers <n>` - 最多同时保留几个语言服务器（`0` = 不用）
- `:errors` - 把当前文件的毛病列成一份清单（只读）
- `:lsp` - 语言服务器的现状：配了哪些、命令找不找得到、现在跑着几个（只读）
- `:ls` - 把打开过的文档列成一份清单（只读，`*` 标当前）

长输出（`:ls` / `:errors` / `:lsp`）会**铺满一屏**而不是挤在一行状态栏里 ——
一行装不下的东西会被从右边切掉，而且切得看不出来。

同时它们会**写进输出文件夹**：

```text
:ls     →  <stbd.exe 旁边>/stbd-out/file_list.txt
:errors →  <stbd.exe 旁边>/stbd-out/error_log.txt
:lsp    →  <stbd.exe 旁边>/stbd-out/lsp_status.txt
```

这三个文件始终存在、内容只在那条命令跑的时候改、**进入时清一次**
（所以不会看见上一次的残留）。意思就是：内容**留到你下次打开编辑器** ——
想在退出之后拿这份清单，就在编辑器还开着的时候读它。想换地方就设 `STBD_OUTBOX`。

清单是两个只读的虚拟视图：能滚动、`q` 退回去时原来那份文档**原样放回**
（不重新读盘、不丢改动）。

**语言服务器**

编辑器**一行分析代码的逻辑都没有** —— 语法、类型、借用全交给外部服务器，
它只负责把诊断画在行号上。内置认 `.rs`（`rust-analyzer`）和
`.c/.h/.cpp/.cc/...`（`clangd`）；**加一门语言是改配置，不是改代码**：

```toml
[lsp.zig]
command = "zls"
extensions = ["zig"]
```

- 出错的那一行行号变红、警告变黄（只有行号变色，正文不动）
- 光标停在哪一行，状态栏就显示那一行的诊断，原文一字不改
- `:errors` 打开完整清单；`q` 退回去，**原来那份文档原样放回**（不重新读盘）
- `:lsp` 告诉你配了哪些服务器、命令找不找得到、现在跑着几个 ——
  「我都没下载，它怎么跑的」「我装了怎么不动」都在这条命令的答案里
- `:set lspmaxservers 0..8` - 最多同时保留几个**进程**（默认 3），调小时多出来的**当场收掉**
- 服务器是用到了才起的，所以只在一个项目里干活时，`1` 和 `8` 完全一样
- 服务器不在、或这不属于任何项目时，**编辑器照常用**，只少诊断
- 键是「命令 + 项目根」：Rust 和 C 混着的项目**自己就要两个**，别把 `lspmaxservers` 压太死

**后台任务**

- `:check` - 在后台跑 `cargo check`，**界面不卡**。回车那一刻状态栏就显示 `Checking…`，
  跑完把 cargo 自己的那句总结报出来（成功是 `Finished …`，失败是 `error: could not compile …`）
- `:fmt` - 在后台跑格式化工具（`rustfmt` 认 `.rs`，`clang-format` 认 C/C++ 那一批后缀），
  **排的是缓冲区里那份、不碰磁盘**，所以没保存的改动不会被丢掉。结果换回来只占
  **一个撤销步**，`u` 就退回去。别的后缀会说 `No formatter for this file type`

> `:fmt` 是项目里**第一个「提供者」**：命令层不写 `if 语言 == "rust"`，而是去
> `src/formatter.rs` 的一张表里按后缀查。加第三个（gofmt、prettier……）只需要
> 往那张表加一条 + 写一个算 argv 的函数。
>
> ⚠️ clang-format 那条路会**认项目里的 `.clang-format`**（`-style=file`）——
> 这跟它在命令行上的默认行为不一样，命令行下不给参数它用的是内置 LLVM style。

**选项**

- `--force` / `-f` - 跳过「未保存改动」的拦截，用在 `:q` `:back` `:next` `:open` `:settings` 上，
  例如 `:open --force a.rs`
- 单独一个 `--` 之后全是位置参数，用来打开以 `-` 开头的文件：`:open -- -weird.rs`

### 5. 技术栈
- **Rust** + **Ratatui**（UI 框架）
- **Crossterm**（终端事件处理）
- **Color-Eyre**（错误处理）
- **文本缓冲区**：使用 `String` 或后续升级为 `Rope`（性能优化）

### 6. 代码架构
- `main.rs`：程序入口，事件循环；启动时读配置文件
- `app.rs`：应用状态（模式、命令缓冲区、光标位置、文本缓冲区）
- `config.rs`：用户配置文件（格式、位置、解析、校验）
- `ui.rs`：界面渲染逻辑
- `event.rs`：事件处理器（线程、Tick、事件转发）
- `update.rs`：业务逻辑更新（按键处理）
- `commands.rs`：命令的解析与执行（`:` 后面那一行）

## 配置文件（`stbd-settings.toml`）

编辑器启动时会读一个叫 `stbd-settings.toml` 的配置文件，用来保存用户偏好（是否显示行号、
Tab 宽度、滚动边距、颜色）。

**最省事的用法**：在命令模式敲 `:settings`。它会打开配置文件让你改；如果还没有配置文件，
就照内置模板在**可执行文件旁边**生成一份。改完 `:w` 保存，再敲一句 `:config reload`
就生效了（不想重载也可以重启 STBD）。

也可以手动放置，查找顺序是「先找到的先用」：

| 优先级 | 位置                                                                                      | 适用场景                             |
| ------ | ----------------------------------------------------------------------------------------- | ------------------------------------ |
| 1      | 环境变量 `STBD_CONFIG` 指定的路径                                                         | 测试 / 多套配置切换                  |
| 2      | 可执行文件同目录的 `stbd-settings.toml`                                                   | **首选**：配置跟着程序走，不碰系统盘 |
| 3      | `%APPDATA%\stbd\stbd-settings.toml`（Linux/macOS 为 `~/.config/stbd/stbd-settings.toml`） | 兜底：exe 目录写不进去时             |

没有配置文件也能正常用（全用默认值）。`:config path` 查看实际用的是哪一个，`:config`
查看当前生效的设置。模板另存在项目根：`stbd-settings.example.toml`。

格式是 TOML，一行一个键值对：

```toml
# `#` 开头是注释
show_line_numbers = true
tab_width = 8
scroll_margin = 3
side_scroll_margin = 5

# 分节要写在文件最后（TOML 规则：分节之后的键都属于那个分节）
[colors]
text = "green"
line_number = "yellow"
```

### 颜色

`[colors]` 分节可以逐个指定界面各部分的颜色：

| 键                | 默认值        | 管哪里                                |
| ----------------- | ------------- | ------------------------------------- |
| `text`            | `green`       | 正文文字（底栏那个文件名也是它）      |
| `line_number`     | `darkgray`    | 行号                                  |
| `error`           | `lightred`    | 出错那一行的行号                      |
| `warning`         | `lightyellow` | 警告那一行的行号                      |
| `current_line_bg` | `#303030`     | 当前行背景（写 `reset` 关掉高亮）     |
| `selection_bg`    | `#354060`     | 选区背景（只读模式下按 `V` 圈住的行） |
| `command`         | `cyan`        | `:` 命令输入                          |
| `mode_readonly`   | `darkgray`    | `-- READ-ONLY --` 标签                |
| `mode_edit`       | `yellow`      | `-- EDIT --` 标签                     |
| `mode_visual`     | `lightcyan`   | `-- VISUAL --` 标签                   |
| `hint`            | `darkgray`    | 快捷键提示                            |
| `status`          | `green`       | 底部状态信息                          |

> 行号是**暗灰**、警告是**亮黄** —— 两个颜色得分开看：行号是背景设施，
> 它得给警告色让位，否则行号栏上分不出「没毛病」和「有警告」。

颜色的写法（大小写不敏感）：

- **具名色**：`black` `red` `green` `yellow` `blue` `magenta`（也认 `purple`）
  `cyan` `gray`（也认 `grey`）`white` `darkgray` `lightred` `lightgreen`
  `lightyellow` `lightblue` `lightmagenta` `lightcyan` `orange`
- **十六进制**：`#ffcc00`，简写 `#fc0` 等价于 `#ffcc00`
- **不染色**：`reset`（也可写 `default` / `none`），即用终端默认色

只写其中几项也行，没写的用默认值。

三个要点：
- **键名写错会直接报错**，不会静默忽略。启动时状态栏会显示原因（带行号）并退回默认值。
- **分节必须写在文件最后**，否则后面的键会被算进那个分节里。
- **运行中用 `:set` 改的设置不会写回文件**（和 vim 一样）。想永久生效请改文件
  并重新启动。

## 界面

```text
1 int main(void) { return 0; }      ← 文本区：没有边框，占满整屏
 2
 3
 broken.c  -- EDIT --  Esc read-only | type to edit | ^Z undo …
 Saved broken.c
```

自上而下三块：**文本区**（占满剩下所有行）、**底栏**（文件名 + 模式 + 提示）、
**状态行**（状态信息，或光标那一行的诊断）。

- **没有边框。** 上下各一行、左右各一格全给了正文 —— 终端里行数本来就稀缺，
  拿两行去画两条横线很亏。文件名搬到了底栏，跟 nvim 的 statusline 一个位置
- 底栏从**右**边截断，所以最左是文件名（最不能丢的），其次是模式，最后才是提示
- 命令模式下这**整行**归输入框，文件名暂时让位（和 nvim 一样）

## 终端与字体

STBD 只负责往终端写字，**字长什么样、占几格是终端字体的事** —— 所以有下面这条
「程序没错、屏幕还是歪」的已知偏差，以及一条挑字体的硬指标。

### ⚠️ 已知偏差：东亚歧义宽度字符

`─` `│` `█` `●` `→` `…` 这类字符在 Unicode 里属于**「东亚歧义宽度」（Ambiguous）**：
它们占几格**没有标准答案**，由字体说了算。

| 谁                                                             | 认为 `─` 占几格 |
| -------------------------------------------------------------- | --------------- |
| STBD（`buffer.rs::char_cells` → `unicode-width` 的 `width()`） | **1 格**        |
| CJK 等宽字体（霞鹜文楷等宽 / MS Gothic / 宋体…）               | **2 格**        |

**后果**：一行里每出现一个这类字符，光标列、横向滚动、右侧截断就偏一格 ——
表现是「按 `l` 走到行尾时，光标提前停在最后一个字左边」，或者横滚之后右边界对不齐。

**怎么自查**：打开 `stbd-settings.example.toml`（第 3、16、26 行都是一串 `──…`），
光标停在那一行上，一直按 `l` 走到头 —— 提前停住就是撞上了。
（`src/lsp/client.rs` 顶部的示意图同理。）

**为什么不干脆改成 2 格**：占几格是**字体**的属性，不是字符的属性。写死 2 格，
用 Cascadia Mono 这类纯 ASCII 等宽字体的人（那些字符本来就是 1 格）反而开始偏 ——
等于把一个字体相关的问题换成另一个字体相关的错。真要做，方向是加一个配置开关去调
`unicode-width` 的 `width_cjk()`（把歧义宽度按 2 格算），但要先知道它**修不全**：
本项目依赖的 0.2.2 里 `width_cjk('✓')` 仍然是 `1`（实测）。

> 换成纯 ASCII 等宽字体确实能避开这些字符的偏差，但它没有中文 —— 中文会掉进
> **字体回退**，字形和宽度都不再由你挑的字体决定。中文项目里还是选一款 CJK 等宽字体。

### 挑字体的硬指标：拉丁 1 格、中文 2 格

实测**霞鹜文楷等宽**（LXGW WenKai Mono）满足：`unitsPerEm = 1000`，
ASCII = 500（1 列）、中文与全角 = 1000（2 列）。

⚠️ 但这个名字**有两套写法，对应两套字体模型**，写错的表现是「静默回退成默认字体，
不报错、看不出哪里错」：

| 谁                          | 用哪套名字            | 为什么                                               |
| --------------------------- | --------------------- | ---------------------------------------------------- |
| Windows Terminal / VS Code  | `霞鹜文楷等宽`        | 走 DirectWrite，认「排版家族名」，` Medium` 只是字重 |
| 控制面板「字体」页 / 记事本 | `霞鹜文楷等宽 Medium` | 走 GDI，显示的是字体文件里的家族名（带字重）         |

```jsonc
// Windows Terminal 的 settings.json → profiles → 某个 profile
"font": {
    "face": "霞鹜文楷等宽",  // 写成 "霞鹜文楷等宽 Medium" 会查不到 → 静默回退
    "weight": "medium",
    "size": 12
}
```
